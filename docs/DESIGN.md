# ケミラボ 設計書

開発指示書「15. 開発AIへの指示」で求められた 7 項目と、設計段階で見つかった問題点・代替案をまとめる。

---

## 1. 推奨する技術構成とその理由

| 項目 | 採用 | 理由 |
|---|---|---|
| 言語 | **素の JavaScript（ES Modules）+ HTML + CSS** | ビルド工程（npm / バンドラ）が不要。GitHub のブラウザ編集画面でファイルを直せば、そのまま GitHub Pages に反映される。**PC なし開発で最も重要な条件** |
| フレームワーク | 使わない（自作の小さな描画関数） | React 等は実質ビルドが必要で、スマホから管理しにくい。画面数が少ないので素の DOM で十分 |
| データ形式 | **JSON**（`data/` 以下） | 化学データとコードの分離。JSON はスマホの GitHub エディタで直接編集できる |
| 保存 | **LocalStorage**（自動保存） | セーブデータは数 KB 程度で十分。IndexedDB は将来データが増えたら移行 |
| オフライン | **Service Worker + Web App Manifest（PWA）** | 一度開けば通信なしで遊べる。ホーム画面に追加するとアプリのように起動 |
| 公開 | **GitHub Pages**（無料） | サーバー不要の静的サイト |
| 品質管理 | **GitHub Actions**（無料） | push ごとに原子数保存などの化学データ検証を自動実行。結果はスマホの GitHub アプリで確認可能 |
| 図の描画 | **SVG（自前描画）** | 構造式・実験器具を外部ライブラリなしで描け、画面サイズに合わせて拡大縮小できる |

TypeScript は型安全の利点があるが、ブラウザで直接実行できずビルドが必要になるため採用しない。代わりに **データ検証スクリプト**と**テスト**で品質を担保する。

## 2. ゲーム全体の画面構成

```
┌──────────── ヘッダー（所持物質数・発見反応数）────────────┐
│                                                            │
│  [実験室]  … メイン画面                                    │
│    ├ 実験ステージ（フラスコ・バーナー・温度/圧力計・演出）│
│    ├ 実験台スロット ×3（タップで追加・✕で除去）          │
│    ├ 条件パネル（温度スライダー＋プリセット / 圧力 /      │
│    │             触媒 / 溶媒 / 操作：光照射・点火）       │
│    ├ [反応開始] ボタン                                     │
│    ├ 試薬棚（ボトムシート：検索・分類・NEW 表示）        │
│    └ 結果シート（成功／条件不一致／非反応／未登録）      │
│  [物質図鑑]  一覧（未発見は ？）→ 詳細（構造式・物性…）  │
│  [反応図鑑]  分野別一覧（未発見はテーマのみ）→ 詳細       │
│  [設定]      研究記録・セーブの書き出し/読み込み・        │
│              データ検証・安全上の注意                      │
│                                                            │
└──────────── 下部タブバー（親指で届く位置）────────────────┘
[研究所]（Phase 2）指導者の会話・研究レベル・章ごとの研究課題・段階ヒント
```

- 操作はすべて **タップで完結**（ドラッグ＆ドロップに依存しない）。
- ボタンは指で押しやすい 44px 以上。主要ボタンは画面下部に固定。
- URL ハッシュでルーティング（`#/zukan/c2h5oh` など）し、ブラウザの「戻る」が使える。

## 3. ゲームの基本的なデータ構造

### 物質（`data/substances.json`）
```jsonc
{
  "id": "c2h5oh", "name": "エタノール", "nameEn": "Ethanol",
  "formula": "C2H5OH",            // 示性式。分子量・原子数はここから自動計算
  "category": "organic", "kind": "化合物", "state": "liquid",
  "color": "#f4f7ff",             // フラスコ内の表示色
  "unlock": "initial",            // initial=最初から所持 / product=生成して入手
  "tags": ["solvent"],            // catalyst / solvent として条件パネルに表示
  "properties": { "mp": -114.1, "bp": 78.4, "pKa": "約 16" },
  "description": "…", "uses": ["…"], "hazards": ["…"],
  "structure": { "type": "molecule", "atoms": [["C",0,0], …], "bonds": [[0,1,1], …] }
}
```

### 反応（`data/reactions.json`）
```jsonc
{
  "id": "r_ethanol_to_ethylene",
  "name": "エタノールの分子内脱水", "field": "organic", "topic": "脱離反応",
  "reactants": [{ "id": "c2h5oh", "n": 1 }],
  "products":  [{ "id": "c2h4", "n": 1 }, { "id": "h2o", "n": 1 }],
  "reversible": false,
  "conditions": [ { "catalyst": ["h2so4"], "temperature": { "min": 160, "max": 200 } } ], // OR で複数指定可
  "advisories": [ { "when": { "temperature": { "min": 551 } }, "text": "…" } ],         // 成功時の注意
  "failHints": { "catalyst": "…", "temperature_low": "…" },                             // 失敗時のヒント
  "thermo": { "dH": 45, "unit": "kJ/mol" },
  "visual": { "effect": "gas" },
  "summary": "…", "mechanism": [{ "title": "…", "text": "…" }], "why": "…", "knowledge": ["…"],
  "safety": { "level": "danger", "text": "…" },
  "related": ["r_ethanol_to_ether"],
  "verification": { "level": "standard", "review": "ai-draft", "sources": ["…"], "simplifications": "…" }
}
```

### 反応しない組み合わせ（`data/non_reactions.json`）
銅＋塩酸のように「反応しないこと自体に学習価値がある」組み合わせと理由。

### 研究課題（`data/missions.json`）と研究レベル（`data/progression.json`）
```jsonc
{ "id": "m_elimination", "chapter": 2, "title": "アルコールからアルケンへ",
  "objective": { "type": "reaction", "id": "r_ethanol_to_ethylene" },   // または nonReaction
  "requires": ["m_neutral"], "minLevel": 1,
  "briefing": { "by": "mizuki", "text": "…" }, "debrief": { "by": "mizuki", "text": "…" },
  "hints": ["分野：…", "物質：…", "条件：…"], "answer": "…",
  "reward": { "xp": 120, "unlock": ["br2", "ccl4"] } }
```
- ヒントを見た数に応じて報酬経験値が減る（1.0 → 0.9 → 0.75 → 0.6、解答閲覧 0.4）。ヒントなしモードで自力達成すると ×1.5。
- 課題は「取り組み中」にしていなくても、目的の実験に成功すれば達成になる（自由実験を妨げない）。
- 研究レベルの到達で試薬が解放される（Lv.2 塩素、Lv.3 ナトリウム・ニッケル、Lv.4 担持リン酸）。
- 検証器は、前提関係の循環・存在しない参照・入手経路のない報酬物質を検出し、さらに**到達可能性解析**で「必要な物質や触媒が手に入らず達成できない課題」がないことを確認する。テストでは自動プレイヤーが新規データから全課題を達成できることを確認している。

### セーブデータ（LocalStorage `chemlab.save`）
```jsonc
{ "version": 1, "owned": [...], "newSubstances": [...],
  "discoveredReactions": { "r_xxx": { "count": 3, "firstAt": 1700000000000 } },
  "discoveredNonReactions": [...], "stats": {...}, "bench": [...], "conditions": {...},
  "log": [...], "flags": {...},
  "settings": { "noHint": false },
  "research": { "xp": 0, "level": 1, "missions": {}, "hints": {}, "answers": {}, "active": null } }
```
読み込み時に `migrate()` で欠損フィールドを補い、データ更新で増減した物質にも追従する。Phase 1（version 1）のセーブは、発見済みの反応・物質から経験値と達成課題を遡って付与して移行する（所持物質は失われない）。

## 4. 化学反応判定エンジンの設計（`js/core/engine.js`）

「物質名の組み合わせ表を引くだけ」にしないため、**反応物の照合 → 条件評価 → 結果分類** の 3 段階で判定する。

1. **候補探索**：選んだ試薬すべてが反応物に含まれ、反応物が「試薬 ∪ 溶媒」で揃う反応を候補とする。
   - 溶媒も反応に参加しうる（例：臭素水中のエチレン → 水が付加してブロモヒドリン）。
   - 余った試薬が溶媒タグを持つ場合は溶媒として扱う（水を試薬として入れても沈殿反応が起こる）。
2. **条件評価**：各候補の条件セット（温度・圧力・触媒・溶媒・活性化）を評価。条件セットは OR で複数持てる（Pt なら常温、Ni なら加熱、など）。
3. **結果分類**
   - `success`：条件を満たす反応あり → 生成物・解説・（条件次第の）注意事項を表示
   - `failed`：反応物は合っているが条件不一致 → **原因とヒント**を表示（答えは直接見せず、分野・テーマのみ提示）
   - `no_reaction`：反応しないことが既知 → 理由を解説
   - `unknown`：未登録 → 「現実に起こらないとは限らない」と明示し、部分一致からヒント

**条件によって生成物が変わる例（実装済み）**
- エタノール＋濃硫酸：約 140 °C → ジエチルエーテル（置換）／約 170 °C → エチレン（脱離）
- エチレン＋臭素：CCl₄ 中 → 1,2-ジブロモエタン／水中 → 2-ブロモエタノール
- エチレン＋水素：Pt は常温、Ni は加熱が必要
- ハーバー法：高温で成功はするが平衡収率低下の注意を表示

エンジンは DOM に依存しない純粋な関数なので、ブラウザと Node（テスト・CI）の両方で同じコードが動く。

## 5. 物質・反応データの管理方式

- **データとコードの完全分離**：物質・反応を追加するときは JSON を編集するだけ。コードの変更は不要。
- **自動検証**（`js/core/validate.js`）— ゲーム内の設定画面と GitHub Actions の両方で実行：
  - 反応式の **原子数保存・電荷保存**（化学式から自動計算）
  - 参照 ID の存在、触媒・溶媒タグの整合
  - **構造式データと化学式の原子数の一致**（座標入力ミスの検出）
  - イオン結晶の電荷の総和が 0 であること
  - 出典・検証状況の記載有無、入手不能な物質の検出
- **検証状況のメタデータ**：
  - `level`: `standard`（教科書標準）/ `simplified`（ゲーム用簡略化あり）/ `uncertain`（不確実）
  - `review`: `ai-draft`（AI 作成・査読待ち）/ `human-reviewed`（専門家査読済み）
  - `simplifications`: 何を簡略化したかを文章で明記 → ゲーム画面にも表示
- **拡張性**：数百〜数千件になったら、分野ごとにファイルを分割（`data/reactions/organic.json` など）し、`db.js` で結合する。読み込みは索引化済み（`substanceMap`, `asReactant` 等）なので件数が増えても判定は高速。

## 6. 開発ロードマップと実装優先順位

| Phase | 内容 | 状態 |
|---|---|---|
| **1** 最小プレイ可能版 | 実験室画面・試薬選択と混合・条件設定・反応判定・生成物表示・構造式（基本）・物質図鑑・基本解説・反応図鑑（簡易）・自動セーブ・オフライン対応・データ検証 | **実装済み（v0.1.0）** |
| **2** ゲーム性 | 研究所タブ／指導者（水城先生）・先輩（朝倉さん）の会話／研究課題 23 件・5 章（段階ヒント 1→2→3→解答、ヒントなしモード）／研究経験値・レベル（8 段階）／物質の段階的解放（レベル・ミッション報酬）／Phase 1 セーブの移行 | **実装済み（v0.2.0）** |
| **3** 化学システム拡張 | pH・濃度・反応時間・収率（量的関係）／多段階合成ミッション／**反応機構の矢印図（巻き矢印）**／分子構造の改良（SMILES からの自動描画の検討）／物理化学（平衡定数・速度論のグラフ）／分析化学（滴定曲線・スペクトル） | |
| **4** 完成度 | 演出強化・効果音／物質・反応データの拡充（生化学含む）／カリキュラム整備／表示速度最適化 | |

各 Phase 終了時に「自動テスト＋実機（スマホ）での通し操作＋既存機能の回帰確認」を行う。

## 7. スマートフォンのみで開発・運用するための注意点

1. **編集**：GitHub アプリ／ブラウザの github.com から直接ファイルを編集・コミットできる。ビルド不要なのでコミット＝公開。
2. **公開設定（初回のみ）**：リポジトリの Settings → Pages → Source を「GitHub Actions」にする。`main` への push ごとに `.github/workflows/pages.yml` がデータ検証に合格した版だけを公開する。数分後に `https://<ユーザー名>.github.io/chem-game/` で公開される。
3. **更新が反映されないとき**：Service Worker のキャッシュが原因。`sw.js` の `CACHE_VERSION` を上げてコミットすると、次回（または 2 回目）の起動で新版に切り替わる。
4. **エラーの確認**：スマホでは開発者ツールが使えないため、エラーは**画面下部に表示**する仕組みを入れてある。データの誤りは設定画面の「検証を実行」か、GitHub の Actions タブで確認できる。
5. **JSON 編集の注意**：カンマの付け忘れ・付けすぎで全体が読めなくなる。コミット後に Actions が赤（失敗）になったら直前の変更を確認する。
6. **セーブデータの消失リスク**：iOS Safari は、ホーム画面に追加していないサイトのデータを **7 日間未使用で削除**することがある。ホーム画面への追加と、設定画面の「書き出し」によるバックアップを推奨。
7. **file:// では動かない**：JSON を fetch するため、ローカルのファイルを直接開くのではなく GitHub Pages 上で確認する。
8. **無料枠**：GitHub Pages・Actions（公開リポジトリ）は無料で、本構成の利用量なら上限に達しない。

## 設計段階で見つかった問題点と代替案

| 要件 | 問題点 | 採用した対応・代替案 |
|---|---|---|
| 「化学的に妥当な反応判定」 | 任意の物質の組み合わせから生成物を**予測する汎用エンジンは、現在の化学でも実現不可能**（研究レベルの課題）。AI に推測させると捏造の危険がある | **検証済み反応データベース＋条件評価**方式。未登録の組み合わせは「未登録（反応しないとは限らない）」と正直に表示する |
| 化学的正確性 | データ作成に AI を使う以上、誤りが入りうる。自動検査で確認できるのは原子数などの形式面のみ | 全反応に **`review: ai-draft`** を付け、画面上でも「専門家による査読待ち」と表示。化学の専門家（大学教員・院生等）の査読を経たものを `human-reviewed` に変える運用を推奨 |
| 構造式の表示 | 手入力の 2D 座標は数千物質では非現実的 | Phase 1–2 は手入力（構造式と化学式の原子数一致を自動検査）。Phase 3 で **SMILES 表記＋自動レイアウト**へ移行を検討。RDKit.js（WebAssembly, 数 MB）は高機能だがオフライン用キャッシュが大きくなるため、軽量な自作レイアウトとの比較検討が必要 |
| 反応機構の視覚化 | 巻き矢印の図を正確に描くには分子ごとの作図データが必要で、データ作成コストが高い | Phase 1 は段階ごとの文章説明。Phase 3 で「代表的な反応機構のみ」作図データを持たせる |
| 数式の表示 | KaTeX 等の外部ライブラリは「外部依存を減らす」方針と衝突 | 下付き・上付き文字は HTML/Unicode で表現。複雑な式が必要になったら KaTeX を**リポジトリ内に同梱**（CDN 不使用）してオフライン動作を維持 |
| 物質の所持数（量） | 「所持状況の管理」を量まで扱うと、試薬が尽きて詰む・作業的になるなど学習体験を損ねる | Phase 1 は「所持している／いない」で管理（一度作れば何度でも使える）。量的関係（mol・収率）は Phase 3 で反応条件の一部として導入 |
| 平衡反応 | 平衡反応は「成功／失敗」で割り切れない | 平衡記号 ⇌ と解説で明示。極端に収率が低い条件は「失敗」と判定し、それが**ゲーム上の基準**であることを `simplifications` に明記 |
| 危険な実験 | ゲームでは爆発的反応なども扱う | 全反応に `safety` を付け、危険度を色分け表示。導入画面と設定画面で「現実で試さない」ことを明示 |
